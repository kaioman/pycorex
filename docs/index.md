## 目的とスコープ

本設計書群は、以下の観点に重点を置いています。

- AI 連携の共通基盤と各プロバイダー固有実装の分離
- 設定オブジェクトとアプリ初期化処理の責務整理
- 生成系 API を扱うクライアントの状態管理と例外設計
- プロンプト生成とワークフロー編集の再利用性
- 生成物の整合性、失敗時のリトライ、例外ハンドリング

## 既存実装との整合性

現時点の実装では、以下の設計方針が確認できます。

- `core/` には共通抽象クラスが配置され、各 AI バックエンドの実装が継承している
- `models/` と `configs/` は設定ドメインと型定義を分離している
- `utils/` にはプロンプト生成や ComfyUI ワークフロー操作の補助ロジックが置かれている
- 例外クラスと基底クラスは `exceptions/` と `core/` に分離されている

一方で、現状の実装には外部ライブラリ依存の強い点と、初期化処理の非推奨警告が残っています。設計書ではその差異を記録し、将来の整理時に再評価する前提とします。
