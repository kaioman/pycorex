# 概要

## 1. プロジェクトの役割

本リポジトリは、複数の AI サービスや生成系ワークフローを安全かつ再利用可能な形で統合するための軽量な Python コア基盤を提供することを目的としています。主な責務としては、以下のような機能をまとめることができます。

- 生成系 API への共通アクセス手段の提供
- 画像生成、画像編集、テキスト生成の横断的な利用
- プロンプト生成の抽象化と再利用可能な構造化モデルの提供
- 設定情報と初期化処理の集約
- ComfyUI ワークフローの編集と実行支援
- 生成時の安全性と失敗時の再試行戦略の導入

## 2. 全体構造の要点

実装としては、以下のような責務分離が確認できます。

- `configs/` : アプリケーション設定と初期化
- `core/` : 共通抽象クラスとベース機能の定義
- `models/` : 設定モデル・各種ドメインモデル
- `utils/` : 生成ロジックとワークフロー補助機能
- `exceptions/` : API 実行時の失敗と制約違反の表現
- `enums/` : 制御・安全性・評価レベルの定義
- `gemini_client.py`, `imagen_client.py`, `uwgen_client.py`, `comfyui_client.py` : 実際のサービス別クライアント

この構造により、AI を利用するアプリケーション側は API の差異よりも、共通インターフェースと設定モデルに集中できる設計になっています。

## 3. 設計の観点

### 3.1 抽象化の境界

`BaseAIClient` と `BaseGeminiClient` は、共通機能である認証・再試行・ファイル名生成・画像 MIME 判定などを持ち、各サービス別クライアントがその上に載る形です。

### 3.2 設定の分離

`PyCorexConfig` は各種設定モデルを集約し、アプリケーション起動時に外部ライブラリの初期化と組み合わせて利用されます。これにより、生成ロジックから環境依存の設定を分離しています。

### 3.3 生成ワークフロー支援

`WorkflowEditor` と `NodeModification` は ComfyUI のワークフロー編集を抽象化しており、画像生成時にプロンプトやノード設定を差し替える基盤になっています。

### 3.4 例外処理

`NoCandidatesError`、`APIError`、`ComfyUIAPIError` のような例外群により、失敗理由を呼び出し側で識別しやすくなっています。

## 4. 代表的な実装単位

| ファイル / モジュール | 主な責務 | 代表的な機能または備考 |
|---|---|---|
| `pycorex.core.base_ai_client` | 共通 AI クライアント基盤 | リトライ、ファイル名生成、画像 MIME 推定の共通処理 |
| `pycorex.core.base_gemini_client` | Gemini 系 API の共通定義 | 言語、アスペクト比、安全フィルタ、危険カテゴリの共通 Enum |
| `pycorex.gemini_client` | Gemini を利用したテキスト生成 | `generate_text()`、`generate_image()` などの実装 |
| `pycorex.imagen_client` | Imagen を利用した画像生成・編集 | `generate_image()` と `edit_image()` による画像処理 |
| `pycorex.uwgen_client` | Uwgen API 連携 | テキスト生成、画像生成、編集、解析の統合インターフェース |
| `pycorex.comfyui_client` | ComfyUI API 連携 | 画像アップロード、履歴確認、ワークフロー 실행支援 |
| `pycorex.utils.prompt_generator` | プロンプトジェネレーター管理 | 登録済みジェネレーターのファクトリ制御 |
| `pycorex.utils.pony_prompt_generator` | 具体的なプロンプト生成実装 | ステージ、衣装、カメラ条件に基づくプロンプト組み立て |
| `pycorex.utils.workflow_editor` | ワークフロー編集 | ノード修正を適用して生成条件を差し替える処理 |
| `pycorex.configs.pycorex` | 設定モデル集約 | `GeminiModel`, `VertexaiModel`, `PromptModel` などを保持 |
| `pycorex.models.prompt` | プロンプトの構造化データ | `PromptContextModel` による入力・出力構造管理 |
| `pycorex.enums.rating_level` | 安全性・制限の表現 | コンテンツレベルを数値化した評価層 |

## 5. 設計上の注意点

現状の実装は、プロジェクト固有の責務を汎用的な AI アダプター設計として整理する方向性に整っています。ただし、以下の点は今後の設計整理対象として明示されます。

- `app_init.py` は非推奨警告が含まれており、初期化 API の新旧が混在している
- `libcore_hng` への依存が強く、配置の再利用性は外部パッケージに依存している
- `configs` と `models` の責務は概ね整理されているが、設定のライフサイクルとドメイン境界の明文化が必要である
- 生成系 API と ComfyUI の監視ロジックは、監査項目やログ指針を一段高度化できる余地がある

## 6. 設計書の位置づけ

本設計書群は、コードの実装論理よりも「責務の整理」「設計ルール」「運用方針」を主眼に置いています。したがって、詳細な実装コードの解説ではなく、次のような観点で内容を再構成しています。

- 何を抽象化しているか
- どこで境界を設けるべきか
- どの責務が外部依存か
- どのルールを守ってコードを成長させるか

これは、将来の機能追加や新規 AI プロバイダー追加時に、同一レイヤーでの実装差分を小さく保つための指針として重要です。
